# Симулятор адаптивного масштабування сервісів

Програма для експериментальної перевірки методу **самокоригованого запасу ресурсів**
(3-тя стаття, розділи 2–4 дисертації).

## Запуск

```bash
cd "4-курс/Програма"
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python run_experiment.py
```

Триває близько 2 хв на 8 ядрах (прогони йдуть паралельно). Результати з'являються в папці `results/`:

| Файл | Що містить |
|---|---|
| `summary.md` | Усі таблиці (середнє ± стандартне відхилення, 30 прогонів) для двох моделей шуму |
| `summary.csv` | Те саме для Excel, включно з усією сіткою фіксованих k |
| `sensitivity.csv` | Чутливість до параметрів методу W і q |
| `fig1_scheme.png` | Рис. 1 статті: схема циклу керування (окремий скрипт `make_fig1.py`) |
| `fig2_load.png` | Рис. 2 статті: приклади навантаження і дві моделі шуму |
| `fig3_tradeoff.png` | Рис. 3 статті: ресурси vs порушення SLO (4 сценарії) |
| `fig4_timeline.png` | Рис. 4 статті: як запас k(t) підлаштовується під мінливість |
| `tradeoff_white.png`, `tradeoff_ar.png` | Повні версії компромісу для всіх 6 сценаріїв |

Попередня версія (жовтень 2026, лише білий шум) збережена в `results_v1/`.

## Файли

- `simulator.py` — модель сервісу, прогноз (метод Холта), стратегії масштабування, генератор навантаження.
- `run_experiment.py` — запуск експериментів, аналіз, таблиці й графіки.

## Що порівнюється

- **Reactive (HPA)** — рішення за поточним навантаженням.
- **Прогноз + фіксований запас k** — сітка k = 0.00…0.60 з кроком 0.05.
  З неї для кожного сценарію визначається «ідеально підібраний вручну» k.
- **Adaptive (запропонований)** — запас k(t) = q-квантиль недооцінок прогнозу за останні W хв.

Ключове порівняння — **за однакового рівня SLO**: скільки ресурсів знадобилося б фіксованому
запасу, щоб досягти того самого рівня порушень, що й запропонований метод.

## Моделі шуму навантаження

| Назва | φ | Зміст |
|---|---|---|
| `white` | 0 | кожна хвилина незалежна (спрощення) |
| `ar` | 0.8 | відхилення тримається кілька хвилин, як у реальних трасах |

## Параметри моделі (у `simulator.py`)

| Параметр | Значення | Зміст |
|---|---|---|
| `MU` | 50 запитів/с | продуктивність однієї репліки |
| `STARTUP_DELAY` | 3 хв | час запуску нової репліки |
| `TARGET_UTIL` | 0.70 | цільове завантаження |
| `SLO_LATENCY` | 200 мс | допустимий час відповіді |
| `Adaptive.WINDOW` | 60 хв | пам'ять про помилки прогнозу (у чутливості: 30/60/120) |
| `Adaptive.QUANTILE` | 0.90 | яку частку недооцінок покриває запас (у чутливості: 0.80/0.90/0.95) |
| `K_GRID` | 0.00…0.60 | сітка фіксованих запасів для порівняння |
